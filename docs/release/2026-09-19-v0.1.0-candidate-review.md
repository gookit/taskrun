  `DefaultDynamicOutputLimit`；`Status` = `succeeded` / `succeeded_with_warnings` /

## 已知限制

- 默认进程后端的分层清理：Windows 优先创建 Job Object 并把步骤进程放进其中；受限宿主
  （如 GitHub Actions Windows runner）拒绝嵌套指派时，默认 `TreeKillAuto` 退化为按活动父
  进程链终止整棵树（子孙仍被清理），不会静默退化为只杀父进程；需要严格语义的调用方用
  `ProcessEngine{TreeKill: TreeKillRequired}` 在启动前得到明确错误。POSIX 使用进程组。
- 动态变量不能决定进程 Env 与工作目录（设计要求），引用会报 invalid_definition；
  Inspect 标记 Deferred。
- Shell 必须显式指定，且同一份 Shell 源码不承诺跨平台等价。
- Inspect 对依赖动态变量的条件/字段只做保守的文本判定，可能把可静态求值的条件标为
  Deferred（不会误执行）。
- 发现（discovery）必须显式传参，不读父目录或网络。
- Kite 侧列表/搜索/`--show` 仍由旧 Runner 解析（只读展示路径）。
